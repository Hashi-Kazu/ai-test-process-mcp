## 4. 品質特性 × 要件のマッピング指示

### 4.1 製品品質特性

### QC-01 機能適合性(functional suitability)

利用者が必要とする機能を、過不足なく正しく実現できているかを表す特性。

- QC-01-01 完全性: 要件で定義された機能が漏れなく実装されているか / 業務フロー上、必要な操作の入口・出口がすべて用意されているか(関連: functional-testing)
- QC-01-02 正確性: 計算結果や判定結果が仕様どおりの値になるか / 境界値・特殊値を含めて期待結果と一致するか(関連: functional-testing, test-condition)
- QC-01-03 適切性: 実現された機能が利用目的・利用シーンに合っているか / 類似機能との使い分けが利用者にとって迷いにくいか(関連: functional-testing, test-perspective)

### QC-02 性能効率性(performance efficiency)

限られた資源・時間の中で、期待される処理能力を発揮できるかを表す特性。

- QC-02-01 時間効率性: 応答時間・処理時間が想定した範囲に収まるか / 想定される最大負荷時にも許容できる応答が保てるか(関連: non-functional-testing)
- QC-02-02 資源効率性: CPU・メモリ・ストレージ等の使用量が想定範囲内か / 長時間稼働時に資源使用量が単調に増え続けないか(関連: non-functional-testing)
- QC-02-03 キャパシティ: 想定される最大同時利用者数・データ量に耐えられるか / 上限を超えた場合の挙動が安全側か(関連: non-functional-testing, system-testing)

### QC-03 互換性(compatibility)

他のシステムや環境と共存・連携できるかを表す特性。

- QC-03-01 共存性: 同一環境上の他システムと資源を奪い合わず動作できるか / 他システムの動作に悪影響を与えないか(関連: integration-testing, non-functional-testing)
- QC-03-02 相互運用性: 外部システムとのデータ連携・API連携が仕様どおり成立するか / 連携先の異常応答時にも適切にハンドリングできるか(関連: integration-testing)

### QC-04 使用性(usability)

利用者が目的を達成するまでの分かりやすさ・使いやすさを表す特性。

- QC-04-01 認知的な把握しやすさ: 初めて画面を見た利用者が用途を理解できるか / 操作の結果が視覚的に分かりやすくフィードバックされるか(関連: non-functional-testing)
- QC-04-02 習得しやすさ: マニュアルなしで基本操作を習得できるか / ヘルプ・ガイダンスが必要な場面で提供されているか(関連: non-functional-testing)
- QC-04-03 運用しやすさ: 日常的な操作の手数が過剰でないか / 頻出操作にショートカットや一括処理が用意されているか(関連: non-functional-testing, acceptance-testing)
- QC-04-04 ユーザーエラー防止: 誤操作・誤入力を事前に防ぐ仕組みがあるか / 取り消し不可な操作の前に確認が入るか(関連: non-functional-testing)

### QC-05 信頼性(reliability)

決められた条件下で機能を継続して発揮できるかを表す特性。

- QC-05-01 成熟性: 通常運用条件下で障害が発生しにくいか / 既知の不具合が主要な業務シナリオに残っていないか(関連: system-testing, non-functional-testing)
- QC-05-02 可用性: 必要な時間帯にサービスが利用可能な状態を保てるか / 計画メンテナンス以外での停止が想定より多くないか(関連: non-functional-testing)
- QC-05-03 障害許容性: 一部機能・一部コンポーネントの異常時に全体が停止しないか / 異常系入力に対して想定外の停止をしないか(関連: non-functional-testing)
- QC-05-04 回復性: 障害発生後、想定時間内にサービスを復旧できるか / 復旧後にデータの整合性が保たれているか(関連: non-functional-testing)

### QC-06 セキュリティ(security)

情報や機能を不正なアクセス・改ざんから保護できるかを表す特性。

- QC-06-01 機密性: 権限のない利用者が情報にアクセスできないか / アクセス制御が権限区分どおりに機能するか(関連: non-functional-testing)
- QC-06-02 インテグリティ: データが不正に書き換えられていないことを検証できるか / 改ざん検知の仕組みが機能するか(関連: non-functional-testing)
- QC-06-03 否認防止性: 実施した操作を後から本人が否認できない証跡が残るか(関連: -)
- QC-06-04 責任追跡性: 操作履歴から実行者・実行内容を追跡できるか(関連: -)
- QC-06-05 真正性: 利用者・システムの身元が正しく認証されるか / なりすましによるアクセスを防止できるか(関連: non-functional-testing)

### QC-07 保守性(maintainability)

変更・修正・解析のしやすさを表す特性。

- QC-07-01 モジュール性: 機能が独立したモジュールに分割されているか / 一部モジュールの変更が他へ波及しにくい構造か(関連: component-testing, structural-testing)
- QC-07-02 再利用性: 共通処理が他機能・他プロジェクトで再利用できる形になっているか(関連: component-testing)
- QC-07-03 解析性: 不具合発生時に原因箇所を特定しやすいログ・情報が残るか(関連: structural-testing)
- QC-07-04 修正性: 仕様変更時の修正影響範囲が局所化されているか / 修正が既存機能に副作用を与えないか(関連: change-related-testing)
- QC-07-05 試験性: テスト用のフックやモック差し替えが可能な作りか / テストに必要な状態設定・観測が容易か(関連: component-testing, test-condition)

### QC-08 移植性(portability)

異なる環境へ移行・設置・置き換えできるかを表す特性。

- QC-08-01 適応性: 異なるOS・ブラウザ・端末で動作環境に合わせて動くか(関連: system-testing)
- QC-08-02 設置性: 導入手順どおりにインストール・初期設定が完了できるか / アンインストール時に環境が正しく元に戻るか(関連: acceptance-testing)
- QC-08-03 置換性: 旧システム・旧バージョンからの切り替えが円滑に行えるか / 移行データが欠落・破損なく引き継がれるか(関連: change-related-testing)

### 4.2 利用時品質特性

### QU-01 有効性(effectiveness)

利用者が指定された利用状況の中で、目的とする結果を正確かつ完全に達成できるかを表す特性。

- QU-01-01 達成の正確さ: 利用者が意図した結果と実際の結果が一致するか / 操作の完了状態が利用者にとって曖昧でないか(関連: acceptance-testing)
- QU-01-02 達成の完全性: 目的達成に必要な一連の操作を、迂回や補助なしに最後まで終えられるか / 一部の利用者層・利用経路だけ達成できない抜け道が無いか(関連: acceptance-testing, functional-testing)

### QU-02 効率性(efficiency)

目的の達成までに利用者が投じる労力・時間・資源に対して、得られる成果が見合っているかを表す特性。

- QU-02-01 達成までの手数の少なさ: 目的達成までの操作回数・入力量が不必要に多くないか / 同じ目的を持つ利用者が繰り返し同じ手間を強いられていないか(関連: acceptance-testing, non-functional-testing)
- QU-02-02 達成までの時間の短さ: 目的達成までに要する体感時間が許容範囲か / 待ち時間・行列など利用者側の外部要因を含めても許容範囲か(関連: non-functional-testing)

### QU-03 満足性(satisfaction)

利用者が実際に使ってみて、期待や欲求がどれだけ満たされたと感じるかを表す特性。

- QU-03-01 実用性の実感: 利用者が『役に立った』と実感できる結果が得られるか(関連: acceptance-testing)
- QU-03-02 信頼感: 表示された情報・状態を利用者が疑わずに信じて行動できるか / 誤った情報や不確かな表示によって利用者が不安になる場面が無いか(関連: acceptance-testing)
- QU-03-03 快適さ: 操作の過程に不快感・苛立ちを感じさせる要素が無いか(関連: -)
- QU-03-04 心理的負担のなさ: 失敗したらどうしようという不安を抱かせる場面が無いか / 利用者が急かされている・監視されていると感じる要素が無いか(関連: non-functional-testing)

### QU-04 リスク回避性(freedom from risk)

利用に伴って生じうる不利益・危害を、許容できる水準まで抑えられているかを表す特性。

- QU-04-01 経済的損失の回避: 誤操作・システム不具合によって利用者に金銭的損失が生じないか / 二重決済・過剰請求など金銭に関わる異常系が防止されているか(関連: non-functional-testing)
- QU-04-02 健康・安全上の危害の回避: 利用者・従業員の身体的な安全（滞留・混雑・誤誘導等）が損なわれないか / 緊急時に安全側へフォールバックする設計になっているか(関連: acceptance-testing)
- QU-04-03 環境・組織への悪影響の回避: システムの誤動作が周辺設備・他システム・組織運営に悪影響を及ぼさないか(関連: -)

### QU-05 利用状況網羅性(context coverage)

想定した利用状況だけでなく、想定外の状況や利用の広がりにも対応できているかを表す特性。

- QU-05-01 想定利用状況の網羅: 洗い出したすべての利用状況（利用者属性・環境・時間帯・繁閑）で目的を達成できるか / 特定の利用状況だけを想定して他が欠落していないか(関連: system-testing)
- QU-05-02 想定外状況への適応力: 想定外の利用状況（初めての利用者・非定型な操作順序・複合的な例外）でも致命的な失敗に至らないか(関連: non-functional-testing)
