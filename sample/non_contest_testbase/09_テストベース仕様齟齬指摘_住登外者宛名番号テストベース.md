# 住登外者宛名番号テストベース 仕様齟齬指摘

## 0. 本書の位置づけ

本書は `review_test_basis` の意味的レビュー用チェックリスト（`sample/non_contest_testbase/08_テストベースレビュー結果_住登外者宛名番号テストベース.md`
の2章 TB-01〜TB-13）を適用して**人手で作成した文書であり、ツール出力そのままではない**。
したがって `sample/non_contest_testbase/00_成果物生成手順.md` 第3章の**再現性 `diff` の対象外**である。

`review_test_basis` の入力は `documents` / `idPatterns` / `additionalAmbiguousTerms` の3キーだけであり、
生成済み markdown を入力に取る口を持たない。よって「自分の成果物に対して `review_test_basis` を実行する」ことは
仕様上できない。本書は「テストベース2文書に対して `review_test_basis` を実行し、その出力の意味的チェックリストを
人手で適用した結果」である。

指摘IDは **`SF-01` 以降**を使う。`sample/non_contest_testbase/07_要件分析結果_住登外者宛名番号テストベース.md` 3章の指摘表が
ツール生成で `F-01`〜`F-28` を使っているため、記号を衝突させないためである。

### 0.1 該当箇所の表記

`該当箇所` は `文書名:行番号` 形式で示す。行番号は `.work/testbase/atenabango/*.txt`
（`scripts/extract-testbase-xlsx.mjs` が xlsx 原本から抽出したテキスト）の行番号である。
抽出は決定的であり、同一の原本からは常に同一のテキストが得られることを `00_成果物生成手順.md` 第3章で確認している。

文書名の略号は以下のとおり。

## 2. 決定的検査の限界（本書を必要とする理由）

`08_テストベースレビュー結果_住登外者宛名番号テストベース.md` の1章と
`07_要件分析結果_住登外者宛名番号テストベース.md` の2章が行う決定的検査は、次の3種類の齟齬を**構造的に検出できない**。
本書の16件のうち13件（SF-01〜SF-10、SF-12〜SF-14）がこの3種類に該当する。

1. **同一対象に対する2文書の記述の突き合わせ**。決定的検査は文書ごとにトークンを数えるため、
   「住所_町字の桁数が 18 と 120 で食い違う」（SF-01）のように、項目名を鍵にして値を突き合わせる比較は行わない。
   同義語（SF-02 / SF-03）についても、双方が自身の文書内では整合するため指摘に現れない。
2. **片側の文書にのみ存在する項目の検出**。決定的検査は「定義されたID」を起点に索引を作るため、
   IDを持たないリクエストパラメータやレスポンス項目（SF-05 / SF-06）は索引に入らない。
   項目定義書側にのみ存在する 031-25（SF-04）は、こちらが `exclusions` に宣言して初めて `01_` 2.3 に現れる。
3. **記述の欠落**。並行時の扱い（SF-14）、再依頼の回数と間隔（SF-13）、版番号（SF-12）のように
   「書かれていないこと」は、数量表現にも曖昧語にも未解決参照にも現れない。

加えて、決定的検査が出した指摘のうち**仕様欠陥ではないもの**が確かに存在する（SF-15 / SF-16）。
未解決参照2件はいずれも抽出パターンに起因する偽陽性であり、境界語なし30件の大半は書式説明である。
決定的検査の指摘件数をそのまま仕様欠陥の件数として報告してはならない。
