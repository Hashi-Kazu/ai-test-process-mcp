**スコープ:** 住登外者宛名番号付番API（app_submit/v10/jutogaishaatenabangofuban）の要求電文・応答電文と、住登外者宛名基本情報の項目定義（データ項目ID 031-1〜031-29）の整合をテスト対象とする。付番APIの入出力で設定または確認できる項目に限定し、付番APIに対応パラメータを持たない項目定義書側だけの項目（031-25 代表宛名フラグ）はテスト対象外として4章に列挙する。認可サーバによるアクセストークン発行そのもの、および基幹業務システム側の画面・帳票はテスト対象外とする。

**目的・目標:**

## 4 テスト対象外機能

- データ項目 031-25 代表宛名フラグ: 付番APIのリクエストパラメータ（fuban-api_spec:96-155）にもレスポンスオブジェクト（同:167-199）にも対応項目が存在せず、付番API経由では値を設定も確認もできないためテスト対象外とする。APIは別項目である名寄せ元フラグ nayosemotofuragu（同:149）を持つ。項目定義書側にのみ存在する事実は仕様齟齬として別途記録する
- 認可サーバによるアクセストークンの発行処理: 本APIの要求元認証は OAuth2.0 client_secret_jwt（fuban-api_spec:37）であるが、認可サーバそのものは住登外者宛名番号管理機能の外側の構成要素であり、本仕様書はその内部処理を規定していない。アクセストークンの検証結果（有効／無効）を入力条件として扱うにとどめる
- 統一ID基盤の整備を前提とする将来の認証方式: fuban-api_spec:38 が「今後国で統一ID基盤の整備が検討されている」として暫定措置に言及しているだけで、実装対象の仕様が確定していない
- オンプレミス環境で当面認められる API Key 認証: fuban-api_spec:40 が「あくまで時限的な措置」と位置づけており、ガバメントクラウドでは原則認めないとされているため、本計画では対象としない
- 住登外者宛名番号付番API以外のAPIコール: fuban-api_spec:27-29 が提供するAPIコールを app_submit/v10/jutogaishaatenabangofuban の1件のみと定めている
- コードID 999 自治体固有コード（item-definition:72）の個々のコード値: 地方公共団体が任意に規定するコードであり、標準仕様書側で値が確定していない
- データ型 9V / S9 / BLOB / YEAR（item-definition:114-122）: 凡例に定義はあるが、住登外者宛名基本情報の29項目のいずれにも使用されていない
