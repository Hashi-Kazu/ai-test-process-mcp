# 2025年テストベース基準 成果物生成手順

本書は `sample/2025/` 配下の成果物を **誰でも同じ入力から同じ出力に再生成できる** ようにするための手順書である。
対象は ASTER テスト設計コンテスト 2025年版テストベース（`sample/2025/2025_tdc_open_testbase/` の PDF 9文書）。

追跡: GitHub Issue #73（親 #69） / Jira HSKZ-117。

---

## 1. 工程の全体像

| 工程 | 内容 | 使用ツール | 状態 | 成果物 |
| --- | --- | --- | --- | --- |
| **A** | ID母集団監査（実在ID母集団と対象／除外の理由付き宣言の確定） | `audit_id_population` | **実施済み（本コミット）** | `sample/2025/01_ID母集団監査_2025テストベース.md` |
| B | テスト計画書の生成・レビュー | `generate_test_plan` / `review_test_plan` / `revise_test_plan` | 未実施 | - |
| C | テスト分析（テスト条件抽出・要求分析） | `analyze_requirements` / `extract_test_conditions` | 未実施 | - |
| D | テスト設計（テストケース生成・探索的チャーター） | `generate_test_cases` / `design_boundary_values` / `design_equivalence_partitioning` / `generate_exploratory_charters` | 未実施 | - |
| E | 2026年版との差分再展開 | `reexpand_threshold_changes` | 未実施 | - |

**工程B〜Eはすべて工程Aで確定した母集団を分母として使う。** 工程Aの宣言（`sample/2025/payloads/audit-id-population.json`）と
実際に工程B〜Dへ投入した母集団が食い違った場合は、payload を直して工程Aを再実行し、差分を成果物に反映する。

## 3. 実行コマンド（工程A）

```
# 1. テストベースPDFを全文テキスト化（-> .work/testbase/2025/*.txt が9件）
bash scripts/extract-testbase-text.sh 2025

# 2. audit_id_population を実行して監査結果を生成
node scripts/call-mcp-tool.mjs \
  --tool audit_id_population \
  --payload sample/2025/payloads/audit-id-population.json \
  --documents-dir .work/testbase/2025 \
  --documents-key documents \
  --out "sample/2025/01_ID母集団監査_2025テストベース.md"
```

`scripts/call-mcp-tool.mjs` は `--documents-dir` のディレクトリ内の `*.txt` をファイル名昇順で読み、
`{name, content}` 配列として payload の `--documents-key` へ注入する。`name` は拡張子を除いたファイル名になる。

### 3.1 再現性の確認

```
bash scripts/extract-testbase-text.sh 2025 \
  && ls .work/testbase/2025/*.txt | wc -l \
  && node scripts/call-mcp-tool.mjs --tool audit_id_population \
       --payload sample/2025/payloads/audit-id-population.json \
       --documents-dir .work/testbase/2025 --documents-key documents \
       --out .work/audit-rerun.md \
  && diff .work/audit-rerun.md "sample/2025/01_ID母集団監査_2025テストベース.md" \
  && grep -n "未宣言: 0 " "sample/2025/01_ID母集団監査_2025テストベース.md" \
  && grep -n "未投入文書数: 0" "sample/2025/01_ID母集団監査_2025テストベース.md"
```

`.txt` が9件、`diff` が無出力になれば、コミット済みの監査結果は payload から完全に再生成できている。

## 4. テストベース全文テキストをコミットしない方針

`scripts/extract-testbase-text.sh` の出力先は `.work/testbase/<year>/` で、`.gitignore` により Git 管理外にしている。

理由:

- 抽出テキストは ASTER 提供資料（テスト設計コンテスト テストベース）の**逐語全文**である。本リポジトリは公開リポジトリであり、
  `AGENTS.md` の「原典の逐語転載はしない（パラフレーズのみ）」という方針に反する。
- 同じ理由で、payload JSON にも本文テキストを埋め込まない。payload に持たせるのは
  「文書名」「対象と宣言するID」「除外するIDとその理由」だけであり、本文は実行時に `--documents-dir` から注入する。
- PDF 原本は `sample/2025/2025_tdc_open_testbase/` にそのまま置かれているため、抽出物を捨てても再現性は失われない。

成果物 markdown に含まれる原典由来の文字列は、ID・章節見出し・除外理由に付した短い引用に限る。

## 5. 2025年版を基準に採用した理由

- `sample/2026/` の既存5ファイルは2026年版テストベースを前提に作られており、2026年版のみに存在する情報
  （後述の入場制限人数の具体値、版名 `V03` など）が本文に混入している。2025年版基準の成果物を別に用意することで、
  「どの年のテストベースから導いた記述か」を切り分けられる。
- 2025年版は入場ゲートハブ追加・入場ゲート複数台化という**明確なシステム差分**を含み（02号 改版履歴 V1.1.0）、
  差分ベースのテスト設計の題材として成立する。
- 工程Eの「2026差分再展開」は、2025年版を基準線として初めて差分として意味を持つ。

`sample/2026/` の既存5ファイルは本工程では変更しない。2026年版の扱いは工程Eを実施するときに判断する。

## 6. 工程Aで確定した母集団

**件数は必ず `sample/2025/01_ID母集団監査_2025テストベース.md` の 2.8 サマリを正とする。**
本書やIssue本文の数値を転記して使ってはならない（Issue #73 本文の「約135件 / S-39件 / W-49件」は実測と一致しない）。

2026-07-29 時点の実行結果:

- 定義ID総数 162 / 宣言済み 109 / 除外宣言 53 / 未宣言 0 / テストベース未定義ID 0 / 未投入文書 0

IDが定義されている文書は 11号（49件）・13号（38件）・21号（74件）・22号（1件）の4文書。
01号・02号・12号・71号・72号には要求ID／機能IDの定義行が存在しないため、監査結果1.1のダイジェストで
「検出IDが0件」の指摘が4件出る（71号は参照1件のみ）。これは抜粋投入ではなく**文書の性格による正常な結果**であり、
9文書すべての全文を投入していること（2.6が「なし」）で裏付けられる。

### 6.1 除外（対象外）の切り分け方針

除外は53件。除外理由には必ず 01号／02号の記述を紐付けており、「スコープ外」だけの理由は1件もない。

| 除外グループ | 件数 | 根拠 | 対象に残したもの |
| --- | --- | --- | --- |
| 発券機の個別支払い手段処理（`EN-241`〜`EN-243`, `EH-244`, `S-005-02`〜`S-005-16`） | 19 | 01号「変更していない箇所：発券機での決済処理」／スコープ外：決済システム（テストエビデンス有）／差分のない箇所は運用実績で信頼性確保 | 支払い方法の選択分岐 `EH-240` / `S-005-01`、決済成否を契機とする残数の確保・開放 `EK-311` / `EK-321` / `EK-322` |
| 会員登録（`W-001` 系, `W-Mail-001-*`） | 7 | 01号「会員登録・変更・退会…は保証済み」 | 登録済み会員でのログイン `W-003-01` 以降の予約購入・発券・入場 |
| 退会（`W-002` 系, `E-012`） | 4 | 同上（退会） | 利用可能入場券の有無は予約購入側 `W-008`〜`W-010` |
| パスワード再設定（`W-005` 系, `W-Mail-005-*`） | 8 | 同上（会員情報変更） | 再設定後の認証情報によるログイン `W-003-01` |
| 会員情報編集（`W-007`, `W-007-01`） | 2 | 同上（会員情報変更） | 会員情報紐づけ結果を使う発券 `EH-104` / `EH-312` / `W-014-01` |
| お問い合わせ（`W-012` 系, `W-Mail-012-01`） | 4 | 01号「お問い合わせ…は保証済み」 | エラー画面からお問い合わせへの遷移 `W-900-01`〜`W-900-03` |
| 会員登録・会員情報編集・パスワード再設定からのみ参照されるエラー文言（`E-001`〜`E-003`, `E-006`〜`E-011`） | 9 | 参照元画面をすべて除外したため | 予約購入・ログインから参照される `E-004` / `E-005` / `E-013`〜`E-020` |

注意点:

- **入場ゲート（`EG-*`）は対象内**。01号のスコープ記述は「入場ゲートは既存と変更点がないためスコープ外 → 2025年変更点ありとなりスコープ内となる」と
  上書きされている。入場ゲートハブ（`EH-100` / `EH-210` / `EH-300` / `EH-900`）も対象内。
- **Webチケットシステム側のお支払方法選択 `W-008-02` と `E-018` は対象内**。01号がスコープ外にしたのは外部の決済システムと
  「発券機での」決済処理であり、Webチケットシステムは新規開発のため除外しない。
- `E-004` / `E-005` は新規登録画面からだけでなく `W-003-01` ログイン画面・`W-011-01` 入場券分け与え画面からも参照されるため、
  除外せず対象に残している。

### 6.2 `EH-*` プレフィックスの重複について

11号では発券機機能と入場ゲートハブ機能の両方が `EH-` プレフィックスを使い、`EH-100`（発券機起動／ゲートハブ起動）、
`EH-210`（ログイン／QRコード有効無効判定）、`EH-900`（発券機停止／ゲートハブ停止）が**別機能に同一IDで重複**している。
`audit_id_population` はID単位で重複排除するため、母集団上は1件として扱われる。工程B以降でこの3IDを扱うときは
「発券機側」「入場ゲートハブ側」を明示して分けること。質問状候補としても扱う（第8章）。

## 7. 2025年テストベースの実測事実（Issue本文の前提を覆すもの）

以下はすべて `.work/testbase/2025/*.txt` に対する実測結果である。行番号は抽出テキストの行番号。

1. **入場制限人数の具体的な数値は9文書のどこにも存在しない。**
   01号にあるのは「入場制限者数を倍」「入場ゲートを2台追加」という定性的な記述だけ（01号 82〜85行）。
   `30人` `60人` `0〜999人` はいずれも2025年版9文書に出現しない（`999` の出現は11号1328行の購入No. `000〜999` と
   71号181行の乱数4桁のみで、人数とは無関係）。**したがって2025基準の成果物で「入場制限人数 0〜999 の境界値分析」は実施できない。**
2. **最終予約枠は `17:00～17:30`**（21号656行、71号136行）。`16:30～17:00` は2025年版に存在しない。
   なお時間枠開始時刻の同期処理は `10:00〜16:30 の毎時00分・30分`（11号1076行ほか）で、これは最終枠の開始時刻ではなく同期タイミングである。
3. **11号に `EN-241` `EN-242` `EN-243` というプレフィックス逸脱が実在する。** 発券機の `EH-` 系列の中に `EN-` が混入しており、
   前後の `EH-240` 支払い方法選択・`EH-244` 非接触電子マネー支払いと系列が揃わない。仕様側の誤記指摘候補。
4. **ID件数はツール出力を正とする。** Issue #73 本文の「約135件 / S-39件 / W-49件」は実測と一致しない
   （実測は定義ID総数162件、`S-` は38件、`W-` 系は `W-000`〜`W-015` / `W-900` / `W-Mail-*` / `W-xxx-yy` が混在）。
5. **2025年01号に `V01` / `V02` / `V03` という版名は存在しない。** 01号の版表記は改定履歴の日付のみ（初版 2023/4/27、以後
   2023/5/8・2024/5/13・2025/5/7 の改定）。02号は `V1.0.0` / `V1.0.1` / `V1.1.0`。
   2025基準の成果物タイトル・本文に `V03` を使うと2026年版のみの情報が混入するため使用しない。

## 8. 境界値分析の対象の置き換え

第7章1のとおり「入場制限人数」の境界値分析は2025基準では実施できない。工程Dの境界値分析（`design_boundary_values`）は、
**2025年テストベースで仕様値が確定している以下の項目に置き換える。**

| 対象 | 仕様値 | 出典（抽出テキスト行） | 境界の観点 |
| --- | --- | --- | --- |
| 1回の購入枚数 | おとな＋こども合計で最大9枚。合計10枚以上でエラー `E-016`、合計0枚でエラー `E-015` | 02号256行 / 11号569行 / 21号1094行 | 0 / 1 / 9 / 10 |
| 残数アイコン切替閾値 | 現在10（残数10枚以上は「〇」、9枚以下は数字表示、0枚は「×」） | 11号372行・540行・547行・1267行 / 13号376行 | 0 / 9 / 10 / 11 |
| 入場ゲートの判定結果待ち時間 | 入場ゲートハブから1秒以内に判定結果を受信しない場合は入場不可扱い | 11号1153行 | 1秒の直前／直後 |
| 時間枠 | 30分単位（71号は「29分59秒99999…が含まれる時間枠」と表現） | 01号414〜420行 / 02号235〜239行 / 71号142行 | 枠の開始時刻／終了直前／終了時刻 |
| Web予約購入の指定可能日 | 当日から29日後まで | 21号641行 / 71号134行 | 当日 / 29日後 / 30日後 |
| 団体予約購入 | 10人以上は窓口扱い、申込日を1日目として31日目以降が対象 | 02号332〜335行 | 9人 / 10人、30日目 / 31日目 |

「入場制限人数」および「入場制限者数を倍にした後の具体値」は**未定値**として扱い、境界値分析の対象にはせず、
第9章の質問状項目に回す。

## 9. 質問状（未定値・仕様不整合）候補

工程B以降で仕様側へ確認する項目。いずれも本工程で実測により確認した。

1. 入場制限者数（時間枠あたりの上限枚数）の具体値。01号は「倍」としか書かれておらず、変更前後の数値がどの文書にも無い。
   時間枠別残数の上限が決まらないため、重複販売防止の境界値が定義できない。
2. 追加された入場ゲートの台数と運用構成。01号は「入場ゲートを2台追加」と書くが、総台数の明記が無い。
3. `EN-241`〜`EN-243` のプレフィックスが `EH-` でない理由（誤記か意図的か）。
4. 11号で `EH-100` / `EH-210` / `EH-900` が発券機と入場ゲートハブの別機能に重複採番されている理由。
5. Web予約購入の購入可能範囲の記述不一致。01号226行は「30日後まで購入可能」、01号419行・02号238行・21号641行・71号134行は「29日後まで」。
6. Web予約購入の入場日指定の下限の記述不一致。02号238行・71号134行は「現在時刻の1時間後の時間枠から」、21号641行は「当日から29日後まで指定可能」。
