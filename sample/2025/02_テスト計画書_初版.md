## 1 はじめに

### 1.1 スコープ・目的

**スコープ:** 2025年改修で変更または新設された園内チケットシステムの機能（入場ゲートハブの新設、入場ゲートへの機能割り当て変更、入場ゲート2台追加による複数台運用、入場制限者数の倍化に伴う時間枠別残数の扱い）と、それらにつながるWebチケットシステムの予約購入・入場券表示・入場券分け与えの流れをテスト対象とする。外部の決済システムはテストエビデンスが提供済みであるためテスト対象外とし、4章に列挙する。

**目的・目標:**
- 11号 Ver.1.1.0 で記載が変更された EH-400 停止状態表示・EG-100 ゲート起動・EG-220 QRコード情報通信・EK-520 入場券情報一覧同期・Z1-202 いますぐ入場券残数表示・Z2-202 残数表示、および新規記載された入場ゲートハブ仕様が、記述どおりに動作することを確認する
- 72号 Ver.1.1.0 で通信仕様を見直した「入場管理」「入場ゲートハブ」間データと、新規記載された「入場ゲート」「入場ゲートハブ」間データが、記述どおりに連携することを確認する
- 01号のテスト重点項目「システムが長時間稼働することを保証したい」に対し、入場管理の死活管理 EK-530 と各機器の起動・停止機能の品質情報を収集する
- 01号のテスト重点項目「時間枠の重複販売が発生しないことを保証したい」に対し、時間枠別残数の減算 EK-311 と加算 EK-321、購入情報生成 EK-312 と削除 EK-322 の整合を確認する
- 01号のテスト重点項目「密回避が達成できたことの効果を示したい」は、入場ゲートでの入場記録と時間別入場者数の集計という既存の仕組みで既に達成済みであるため、当該既存機能のリグレッション確認として扱う
- 園内側「だんだん開発」とWebチケットシステム側「DEAN2開発」に分割された開発体制に起因する、サブシステム間連携の欠陥を検出する
- 入場ゲートの変更点を対象としたリグレッションテストと、今後の変更時に大きな問題とならないためのリグレッションテストを、2種類に分けて設計する

### 1.2 背景

**現状:** だんだん動物園は入場者の人数制限のため、時間枠での人数制限と予約購入ができる仕組みを開発済みである。予約購入の入口は発券機とWebチケットシステムの2つで、Webチケットシステムは発券機とは別会社による新規開発である。動物園入口には残数表示インジケータが2台設置されている。2025年は入場制限者数が増加できる状況になったこと、および特定の動物の人気により入場者が捌けなくなったことを受け、入場制限者数を倍にし入場ゲートを2台追加する改修を行う（01号 テスト依頼概要）。この改修に合わせて入場ゲートハブが新設され、入場ゲートへの機能割り当てが変更された（02号・11号・72号 V1.1.0）。

**懸念:** 同時入場者数の増加により入場ゲート付近での滞留リスクが増加する（01号）。入場ゲートのハードウェアとソフトウェアは前回まで変更なしであったが2025年は変更ありとなったため、既存の運用実績を根拠にできない。入場ゲートハブは新設機器であり、12号ハードウェア仕様書にハードウェア仕様が収録されていない。園内側とWebチケットシステム側が別会社の分割開発であるため、サブシステム間の連携部分に欠陥が残りやすい。

## 2 テスト対象

**システム概要:**
- 名称: だんだん動物園入場システム（園内チケットシステムおよびWebチケットシステム）
- 目的: 入場時間枠ごとに入場者数を制限しながら入場券を販売し、入場ゲートで入場を記録することで密を回避する
- 利用者: だんだん動物園の入場者（会員およびゲスト）、団体予約購入を扱う窓口係員、だんだん動物園の管理者
- 開発形態: 園内側は「だんだん開発」、Webチケットシステム側は「DEAN2開発」による分割開発。決済システムは決済サービス会社のサービスを利用する（01号 開発体制）
- 詳細: 営業時間は開園10:00・最終入場17:00・閉園18:00（02号）。入場時間枠は30分単位で、当日の最終予約枠は17:00～17:30（21号・71号）。1回の購入はおとなとこども合わせて最大9枚（02号）。10人以上の団体予約購入は窓口扱いで、申込日を1日目として31日目以降が対象（02号）。システム全体の対応言語は日本語のみ（02号）

- 発券機（EH-100〜EH-900、画面 S-001-01〜S-009-01）: いますぐ入場券購入・時間指定入場券購入・予約済み入場券発券・QRコード印刷・入場管理システム連携。2025年改修の変更対象は EH-400 停止状態表示
- 入場ゲートハブ（EH-100 / EH-210 / EH-300 / EH-900）: 2025年改修での新設機器。入場券情報一覧を保持し、入場ゲートから送信されたQRコード情報の有効／無効を判定して応答する
- 入場ゲート（EG-100 / EG-210 / EG-220 / EG-310 / EG-320 / EG-330 / EG-900）: QRコード読み取り、入場ゲートハブへのQRコード情報通信、ゲート開閉制御・LED制御・ブザー制御。2025年改修の変更対象は EG-100 と EG-220。2台追加により複数台運用となる
- 入場管理（EK-100〜EK-900）: 時間枠別残数の配信・取得・更新、購入情報の生成と削除、予約情報応答、会員認証の中継、入場券情報一覧同期、死活管理。2025年改修の変更対象は EK-520 入場券情報一覧同期
- 残数表示インジケータ1（Z1-100 / Z1-201 / Z1-202 / Z1-203 / Z1-900）: いますぐ入場券残数情報取得・いますぐ入場券残数表示・固定文言表示。2025年改修の変更対象は Z1-202
- 残数表示インジケータ2（Z2-100 / Z2-201 / Z2-202 / Z2-900）: 時間枠別残数情報の取得と表示。2025年改修の変更対象は Z2-202
- Webチケットシステム（W-000〜W-015 / W-900、エラー文言 E-004 / E-005 / E-013〜E-020）: 会員向けのログイン・マイページ・予約購入・予約購入履歴・予約購入詳細・入場券分け与え・ログイン用QRコード・入場用QRコード・印刷プレビュー・エラー通知。園内チケットシステムとはVPN経由で連携する

## 5 テスト方針

### 5.1 テストレベル

- 統合テスト: 発券機・入場ゲートハブ・入場ゲート・入場管理・残数表示インジケータ1／2の機器間、および園内チケットシステムとWebチケットシステム間のインタフェースを、72号 データ連携仕様書の通信仕様に沿って確認する
- システムテスト: 園内およびWebでの予約購入から発券、入場ゲート通過までの一連の流れを通しで確認する（01号「園内およびWebでの予約購入、発券そして入場の流れについて特に確認をお願いしたい」）
- 受け入れテスト: だんだん動物園の視点で、01号のテスト重点項目3件に対する達成状況を判定する
- コンポーネントテスト: 01号「各サブシステム単独で確認可能な要求事項については、開発会社がそれぞれテストは実施済み」に基づき本計画では再実施せず、実施済みであることを前提として扱う
