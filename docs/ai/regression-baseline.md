# 決定的検査の回帰ベースライン（2025年版 V03 × 2024年版 V02）

## 1. 目的と適用範囲

本書は、本リポジトリの決定的検査（`audit_id_population` / `analyze_requirements` / `review_test_basis` /
`generate_test_cases` / `review_test_specification` / `analyze_data_flow_timing`）が
**特定のテストベース構成に依存していないかを判定するための基準値**を記録する。

- **基準とするもの**: 同一のツール群・同一の投入方法で、構成の異なる2つのテストベースへ適用したときの決定的検査の出力件数。
- **比較の軸**: 2025年版テストベース（V03構成：入場ゲートハブあり）と 2024年版テストベース（V02構成：入場ゲートハブなし）。
- **いつ再測定するか**:
  1. `src/` 配下の決定的検査ロジック（`testBasisAnalysis.ts` / `idPopulationAnalysis.ts` / `testCaseAnalysis.ts` /
     `testSpecificationAnalysis.ts` / `dataFlowTimingAnalysis.ts` / `basisContradictionAnalysis.ts` /
     `groundingNormalization.ts` など）を変更したとき。
  2. 新しい決定的検査を追加したとき。
  3. `scripts/extract-testbase-text.sh` の抽出条件、または `pdftotext` の版を変えたとき。
     `scripts/extract-testbase-xlsx.mjs` / `scripts/extract-testbase-docx.mjs`（`docs/ai/testbase-ingestion.md`
     の変換規約の参照実装）の変換条件を変えたときも同様に再測定対象へ含める。
- **適用範囲外**: テスト計画書系ツール（`create_test_plan` / `review_test_plan` / `revise_test_plan`）はテストベース文書を
  入力に取らないため、構成差の影響を受けない。本書の対比表には含めない。

**決定的検査の件数をそのまま仕様欠陥の件数として扱わないこと。** 件数は「宣言と実体を機械的に突き合わせた結果の件数」であり、
偽陽性（PDF→テキスト変換に起因するもの、文書の性格による正常な結果）を含む。妥当性の判断は意味的層（呼び出し側）が行う。
2025年版の読み取り注意は `sample/contest_testbase/2025/00_成果物生成手順.md` 3.8 に、2024年版の注意は
`sample/contest_testbase/2024/00_成果物生成手順_V02汎化検証.md` 5章に書いてある。

追跡: GitHub Issue #98（親 #69） / Jira HSKZ-142。

## 3. 対象テストベースの選定と2023年版を使わなかった理由

Issue #98 の本文は **2023年版テストベース**を汎化検証の対象とする想定だった。実測の結果これは成立しないため、
汎化検証の対象を **2024年版**へ変更した。

### 3.1 2023年版が使えない実測事実

`sample/contest_testbase/2023/2023_tdc_open_testbase/2023_tdc_open_testbase/` の9文書に対する `pdfinfo` の Producer と、
`pdftotext -layout -enc UTF-8`（poppler 24.02.0）の抽出文字数:

| 文書 | Producer | ページ数 | 抽出文字数 |
| --- | --- | --- | --- |
| 01号 テスト依頼書 | Microsoft® PowerPoint® for Microsoft 365 | 26 | 17,884 |
| 02号 概要書 | Skia/PDF m115 Google Docs Renderer | 11 | 16,142 |
| **11号 園内チケットシステム要求仕様書** | **Microsoft: Print To PDF** | **32** | **32** |
| 12号 ハードウェア仕様書 | Skia/PDF m115 Google Docs Renderer | 6 | 6,102 |
| 13号 発券機画面仕様書 | Skia/PDF m115 Google Docs Renderer | 36 | 31,292 |
| 21号 Webチケットシステム要求仕様書 | Skia/PDF m115 Google Docs Renderer | 37 | 68,270 |
| 22号 Webチケットシステム画面仕様書 | Skia/PDF m115 Google Docs Renderer | 41 | 41,616 |
| 71号 入場券仕様書 | Skia/PDF m115 Google Docs Renderer | 6 | 10,867 |
| 72号 データ連携仕様書 | Skia/PDF m115 Google Docs Renderer | 10 | 23,428 |

2023年 11号 は `Microsoft: Print To PDF` で出力されており **テキスト層を持たない**。32ページに対して抽出結果は32文字である。
`EH-` / `EG-` / `EK-` / `EN-` / `Z1-` / `Z2-` のID母集団はこの文書だけで定義されるため、2023年版では
`audit_id_population` の実在ID母集団が構築できず、決定的検査へ投入できない。

### 3.2 2023年版を使うために必要なこと（本タスクのスコープ外）

2023年版を回帰ベースラインへ加えるには 11号 のOCRが必要である。**OCRは本タスクのスコープ外とし、実施していない。**
OCRを導入する場合は、抽出テキストの精度（IDの誤認識率・行番号の安定性）自体が指標へ影響するため、
**別Issueとして起票する必要がある**。本書ではその必要性の記録にとどめ、Issue の作成は行っていない。

### 3.3 2024年版を選んだ理由

- 9文書すべてが `pdftotext` でテキスト抽出できる。
- `ゲートハブ` の出現が9文書すべてで0件であり、`EG-220 QRコード有効/無効判定` が入場ゲート内で完結する
  **V02構成**（11号:1110-1113）である。したがって「入場ゲートハブありという前提に依存した検査」を検出できる。
- 5文書（12号・13号・21号・22号・71号）が2025年版と**完全一致**するため、差が出た指標について
  「構成差に起因するのか、検査の汎化不良に起因するのか」を切り分けられる。

## 5. 指標定義と対比表

「2024年版（生）」は `.work/testbase/2024`（`pdftotext` の出力そのまま）に対する測定値、
「2024年版（除去）」は `.work/testbase/2024-stripped`（双方向制御文字を除去した補助版）に対する測定値である。

**Issue #164（HSKZ-188）以降の注記**: 双方向制御文字はツール側（`stripBidiControls` / IQC-05、`src/groundingNormalization.ts`・
`src/documentDigest.ts`）が投入時に自動で除去するため、**`2024年版（生）` を投入しても `2024年版（除去）` と同じ値になる**。
したがって `.work/testbase/2024-stripped/` の補助版の作成と `2024年版（除去）` 列は**次回再測定時に運用不要**であり、
その時点で列を1本へ統合してよい（本タスクの範囲ではsample成果物・`.work/`が無いため再測定は行わず、この節と以下の各指標末尾への
文章追記のみを行った。数値表は据え置く）。

差の解釈は次の3区分で記す。

- **構成差**: V02とV03の仕様内容の違いで説明できる。
- **抽出品質**: PDF→テキスト変換の欠陥（2024年 11号 の双方向制御文字）で説明できる。検査ロジックの問題ではない。
- **汎化不良**: 上の2つで説明できず、検査がV03固有の前提に依存している。
